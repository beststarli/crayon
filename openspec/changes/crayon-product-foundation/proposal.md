## Why

Crayon 首页目前只有展示性的“开始创作”入口，尚缺少用户身份、作品持久化、历史画册和产品介绍，无法形成从创作到长期保存与再次查看的完整体验。现在需要先建立账户、会话、对象存储和导航的产品基础，并明确 PostgreSQL 与 RustFS 的职责边界。

## What Changes

- 新增“关于 Crayon”站内入口与介绍页面，说明产品用途、创作流程、数据保存方式和隐私边界，并预留“为什么创建 Crayon”的创作者故事区。
- 新增仅使用唯一用户名和密码的注册、登录体系，不依赖手机号、短信验证码或邮箱验证。
- 新增短期 Access Token 与长期 Refresh Token 组成的双 JWT 会话机制，支持无感刷新、Refresh Token 单次轮换、并发刷新合并、退出撤销和异常会话失效。
- 新增用户账户页，支持上传头像、修改昵称、修改密码和退出登录；首页增加独立用户头像入口，并更换博客入口图标以避免混淆。
- 新增“我的画册”，按当前用户展示已上传并完成转换的作品历史，支持作品详情、状态反馈和删除。
- 新增基于 RustFS 的图片对象存储能力；PostgreSQL 只保存用户、作品、对象 key 与处理状态等元数据，原图、转换图、缩略图和用户头像存放于 RustFS。
- 重排首页中心区域：桌面端采用左侧画作、右侧标题与纵向入口；移动端采用单列顺序。为“开始创作”增加蜡笔图标，为“我的画册”增加画册图标，并提供“关于 Crayon”入口。

## Capabilities

### New Capabilities

- `about-crayon`: 关于页面的入口、内容结构和访问行为。
- `user-account`: 用户名密码注册登录、账户资料、头像、昵称、密码修改与退出行为。
- `dual-jwt-session`: Access Token 与 Refresh Token 的签发、存储、轮换、无感刷新、撤销和并发控制。
- `artwork-gallery`: 当前用户作品历史、转换状态、详情和删除行为。
- `artwork-object-storage`: PostgreSQL 元数据与 RustFS 图片对象的职责、上传、读取、缩略图、删除和访问控制。
- `homepage-feature-navigation`: 首页双栏构图、创作/画册/关于入口、图标语义、博客与用户入口区分及响应式行为。

### Modified Capabilities

无。现有首页相关 capability 仍位于尚未归档的 change 中，本 change 使用独立增量能力描述产品基础，避免引用尚未进入主规格的路径。

## Impact

- 将增加站内关于页、登录注册界面、账户页、画册页以及对应的 Next.js 路由和服务端接口。
- 将引入 PostgreSQL 用户、Refresh Token、作品和图片对象元数据表，以及数据库迁移流程。
- 将引入密码哈希、JWT、Cookie、安全请求封装和 S3 兼容客户端等依赖。
- 将接入 RustFS，配置私有 bucket、对象 key 规则、预签名上传/读取、缩略图和对象清理策略。
- 将调整首页主体布局、操作按钮、博客图标和新增用户头像入口；未登录访问受保护能力时进入登录流程。
