## Context

项目目前为 Next.js 16、React 19 和 Tailwind CSS 4，首页仍是默认模板；没有现成的主题状态、上传流程或后端服务。白天与夜晚花田油画棒画作已经生成，但仍在本次会话的生成图片目录，实施时需要纳入项目静态资源。详见 `proposal.md`。

## Goals / Non-Goals

**Goals:**
- 以可复用的桌面场景布局承载两套主题，确保桌面与画作在切换时保持同一构图。
- 让文字、入口与画作在宽屏和手机上均保持优先级、可读性和可操作性。
- 在创作功能未接入前提供诚实、完整的入口反馈，之后可替换为正式上传流程。

**Non-Goals:**
- 本变更不设计图片处理、教程生成或账户体系的技术架构。
- 不将生成图片作为首页上传转换能力的质量承诺。

## Decisions

### 1. 将桌面场景分层组织

画作、桌面底面、日光或台灯效果、四角物件、文字与按钮分别布局。这样可在窄屏时独立移动或隐藏装饰元素，并让主题切换只替换对应层。备选方案是将全部物件预合成一张整屏背景图；它会在不同屏幕比例下裁掉关键物件，也不利于保持文字和按钮可访问。

### 2. 使用两张 4:3 花田画作作为主题配对资源

实施时把白天与夜晚生成图复制进 `public/`，使用稳定且描述性的文件名；画作容器固定 4:3，以适配不同视口。白天图来源：`/Users/beststar/.codex/generated_images/01a0de0d-d6b9-75e1-b989-5a898e6214c1/exec-a096b0d3-d41c-47dd-854d-c87a56beac6e.png`；夜晚图来源：`/Users/beststar/.codex/generated_images/01a0de0d-d6b9-75e1-b989-5a898e6214c1/exec-94e4c798-9adb-4da2-822a-45eb6b663534.png`。备选方案是对一张画作使用色彩滤镜模拟夜晚；它无法真实改变画面中的夜间色彩关系。

### 3. 主题由用户选择并持久化

首次进入读取设备颜色偏好；用户切换后把选择保留在浏览器本地。初始化时应避免服务端与客户端主题不一致造成的明显闪动。主题状态统一驱动画作、桌面用光、文字和玻璃控件。备选方案仅使用 CSS 的 `prefers-color-scheme`，但不能满足手动切换和保留选择。

### 4. “开始创作”先打开流程预览

当前阶段主按钮打开轻量、可关闭的预览界面，说明上传、画幅和教程三步，并明确标识“即将开放”。后续创作功能上线时再将入口指向真实流程。备选方案是链接到尚不存在的上传页，会形成死链；直接禁用按钮则无法让访客理解入口用途。

### 5. 克制的玻璃按钮与响应式优先级

按钮采用半透明背景、有限的背景模糊、细边框和柔和高光；主题分别校正底色与文字对比。手机上优先保留品牌、介绍、画作与主按钮；四角物件可重排、缩小或隐藏。降低动态效果的系统偏好下不依赖动画传达信息。备选方案是固定比例缩小整个桌面，会使按钮和文字过小。

## Risks / Trade-offs

- [生成图与原始照片的花朵位置并非逐像素一致] → 首页将其作为受照片启发的油画棒作品展示，不宣称精确复刻；在实施时目视核对双主题画作的对应关系。
- [高密度桌面素材影响加载速度] → 画作使用合适尺寸与压缩格式，首屏优先加载中央画作，装饰素材控制数量与体积。
- [主题初始化可能闪动] → 在页面呈现前应用已保存主题，并检查首次访问、手动切换及刷新场景。
- [装饰物压住信息或造成窄屏裁切] → 分层布局并在手机断点按优先级调整，验证常见视口和长短屏比例。
